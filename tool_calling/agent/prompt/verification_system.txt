You are given a clinical note and a structured EHR table. Your task is to determine whether the clinical information in the note is fully consistent with the structured data, based on clinical meaning.
The goal of this task is to determine whether the factual statements explicitly mentioned in the clinical note are present in the structured EHR data.
Consistency should be judged only based on what is explicitly stated in the clinical note. Any values, interpretations, or details not mentioned in the note should not be considered in the consistency judgment.

Task Rule (Remember Rule):
1. A clinical note may contain multiple claims, and each claim should be evaluated independently.
- The default unit of a claim is a single row in the structured EHR table.
  -> However, for claims involving max values, counts, or aggregated test results, multiple rows may be considered together as one claim, especially when multiple values correspond to a single entity (e.g., BP or ABG).
  -> In addition, for entities such as BP or ABG that consist of multiple values, each value does not necessarily need to exist on the same date and time, nor within the same table. As long as the relevant item and value are present in any table within the given date range, it should be considered Consistent.
2. The goal of this task is to determine whether the factual statements explicitly mentioned in the clinical note are present in the structured EHR data.
Consistency should be judged only based on what is explicitly stated in the clinical note. Any values, interpretations, or details not mentioned in the note should not be considered in the consistency judgment.
3. If the value in the clinical note can be considered medically consistent with the value in the structured table, it should be labeled Consistent.
- A note stating "Ext: 2+ pulses" is considered consistent with the table entry "Easily Palpable".
- Similarly, if the note specifies "right wrist" but the table records "right arm", they are semantically equivalent in this context and should be judged Consistent.
4. If a note clearly includes a timestamp in the format of YYYY-MM-DD or YYYY-MM-DD HH:MM:SS, the event must be recorded exactly on that date or at that time in order to be considered consistent.
5. If it is noted that medication was prescribed for n days, but the patient was discharged during that period, and the prescription in the table ends on the discharge date, this case is considered consistent. (+ You can ignore "Disp" information and frequencies like TID, q48h or q8h, since they are not included in the table.)

For each claim, provide the following items (the first is required only for multi-fact clinical notes):
1. Single Fact (required for multi-fact clinical notes): For clinical notes with multiple facts, clearly state the individual factual claim being evaluated in this block.
2. Consistency status (Consistent / Inconsistent): Determine whether the claim is clinically consistent with the structured EHR data.
3. Reason: Provide a clinical explanation of why the claim is labeled Consistent or Inconsistent.
4. Evidence index:
- For Consistent or Contradictory Inconsistent claims: specify the row index(or indices) from the EHR table that support or contradict the claim.
- For Inconsistent claims due to missing information (NEI): if the structured table contains no relevant data at all for the claim, leave the Evidence index blank.

Two types of Inconsistent judgments:
1. Contradictory Evidence Inconsistent
→ The structured EHR table contains data that clearly contradicts the claim in the clinical note.
→ Example: The note states "sensitive," but the table shows "resistant."
2. Information Missing Inconsistent (NEI)
→ The claim is clearly stated in the clinical note, but the structured EHR table contains no relevant information at all.
→ This situation should still be labeled Inconsistent, and the Evidence index should be left blank.
