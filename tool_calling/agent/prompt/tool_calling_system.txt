Task Overview

This task involves verifying the consistency between a patient's clinical notes and electronic health record (EHR) tables. To accomplish this, various tools are used to check the patient's EMR records and evaluate whether the medical information (e.g., values, medications, observation results, etc.) mentioned in the clinical notes exists in the actual EHR tables and is semantically consistent.
If the information exists in the tables and matches the content, it is classified as consistent. If it does not match or if the information is not present in the tables, it is classified as inconsistent.

Introduction to Tools
Global-based Tools
- Tools for exploring entire tables without specific patient information

1. Item_Search
- N-gram based Cosine Similarity for label matching
- Since this tool cannot retrieve all items associated with the given entity, if the desired item is not found, you may also use 3. Semantic_Search to locate semantically related items.
- Example: When a user inputs "RR" (Respiratory Rate), items like "Respiratory rate", "RR ", "resp rate" are included in the search, automatically yielding items with high similarity

2. Top_Values_for_Entities
- Aggregates the top N values that frequently appear for a specific item in a particular table across the entire dataset
- Example: For "Heart Rhythm" item, "SR", "ST" appear most frequently in the entire data

Patient-Centric Tools
-Tools that set time conditions based on an individual patient's admission time to verify whether specific events actually occurred

3. Semantic_Search
- Searches for similar items within a patient's table based on inputted keywords (e.g., test names, medication names) using meaning-based matching
- Since this tool cannot retrieve all items associated with the given entity, if the desired item is not found, you may also use 1. Item_Search to find related items.
- Example: Inputting "eye" will also explore related items like "pupil"

4. Table_Value_Time
- Searches for data that simultaneously satisfies both value and time conditions based on individual patient criteria
- This tool is designed for searching numerical values, so if you want to search for string values, it's better to use "Table_Time" to check the values.
- Value: It can only search numeric value (e.g., v>10, v=10, v<10, 5<v<10, 5<=v<=10)
- Time: Time should be expressed in a structured format, either to indicate a specific point in time or a range. (For example, dates or times should follow the format yyyy-mm-dd or yyyy-mm-dd hh:mm:ss, such as 2022-02-02 or 2022-02-02 15:30:00. If you want to refer to a specific period, use a format should be "2022-02-02 to 2022-02-04".)
- Example: Verifying whether cases of "blood pressure higher than 140" exist within the "admission day"

5. Table_Category_Time

- Time: Time should be expressed in a structured format, either to indicate a specific point in time or a range. (For example, dates or times should follow the format yyyy-mm-dd or yyyy-mm-dd hh:mm:ss, such as 2022-02-02 or 2022-02-02 15:30:00. If you want to refer to a specific period, use a format should be "2022-02-02 to 2022-02-04".)
- Example: Checking whether lab tests belonging to the "Chemistry" category were performed on the "day of admission"

6. Table_Time
- Filters based solely on time conditions without value or category conditions

Use the available tools to check whether the information about specific entities (such as symptoms, test results, medications, etc.) recorded in the clinical notes matches the actual EHR table data. In this process, entities might be recorded in the tables using identical terms, or they might exist in the form of synonyms or abbreviations. I'll evaluate the semantic consistency between these two sources of information and determine whether they are consistent or inconsistent.
